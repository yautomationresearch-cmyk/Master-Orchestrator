# Content patterns

Turn the subject into a narrative spine before styling the deck. A visual treatment cannot repair a missing argument.

## Core spines

### Explain

Question → mental model → parts → mechanism → example → takeaway → sources

### Persuade

Problem → stakes → insight → solution → proof → tradeoff → ask

### Report

Answer → evidence → drivers → comparison → caveat → implication → action

### Documentary

Hook → context → timeline → turning point → consequence → interpretation → source trail

### Teach a process

Objective → setup → step 1 → step 2 → practice/checkpoint → recap

### Compare

Shared frame → dimension 1 → dimension 2 → implication → decision rule

## Content-to-scene routing

- single memorable claim → `hero` or `takeaway`
- ordered events → `process` or timeline
- categories revealed over time → `map`
- two related concepts → `comparison`
- causal mechanism → `process`, diagram, or bounded `image`
- spatial structure → atlas/map scene
- measured evidence → data scene or evidence composition
- nuance and uncertainty → comparison plus source/caveat scene

## Density budget

Set a visible density budget before implementation:

- low: one claim, one visual anchor, almost no body copy
- balanced: one claim, two to four supporting elements
- high: evidence tables or charts, only when the audience needs them

When a scene exceeds its budget, shorten the copy or split the state. Do not shrink text until it becomes presentation-unsafe.

### Board / data packs

For executive board decks (Orbit Data, Metric Board), default to **high** density on evidence slides. Empty lower thirds and “section label + one giant KPI” layouts fail QA. Use insight headline + proof + chart + so-what (see [data-board-decks.md](data-board-decks.md)).
